# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Unity 3D game (working title "Game3D"), a cyber/neon-city third-person prototype. It started as a shooter (hitscan gun, first-person rig) but the actively-developed direction is a **ZZZ-style action game**: cooldown-based skills instead of ammo, with a HUD of health bar + skill buttons. Code comments and Inspector headers are written in Vietnamese — match that convention when editing existing scripts.

- **Unity Editor version: `6000.0.44f1`** (Unity 6). Open via Unity Hub with this exact version; the `Library/`, `Temp/`, `obj/`, and `*.csproj`/`*.sln` files are all auto-generated by the Editor and are git-ignored (the `.csproj` files visible in the repo root are regenerated, not tracked).
- **Render pipeline:** Universal Render Pipeline (URP 17.0.4). Materials/shaders must be URP-compatible.
- **Key packages:** Cinemachine 3.1.6, Input System 1.13.1, AI Navigation (NavMesh) 2.0.11, Post Processing, Timeline.

## Build / run / test

There is no command-line build, lint, or test workflow — this is an Editor-driven project.

- **Run:** open the project in Unity and press Play. The only scene in the build list is `Assets/Scenes/SampleScene.unity`; other scenes (`CyberFuture`, `CyberScene`, `BulletCheck`, `RagDoll`, plus vendor demo scenes) are opened manually in the Editor.
- **Tests:** `com.unity.test-framework` is present but no first-party tests exist; it is only pulled in by vendored packages. There is nothing to run.

## Git LFS — important

`.gitattributes` routes `*.png`, `*.tif`, and `*.asset` through **Git LFS**. Ensure `git lfs` is installed before cloning/committing, or these binaries will be broken pointers. Adding new textures or `.asset` files commits them via LFS automatically.

## Where the actual game code lives

The `Assets/` tree is dominated by **third-party asset packs** that should be treated as vendored / read-only: `_DLNK` (Neon City), `Sci-Fi Styled Modular Pack`, `Hayq Art`, `Polytope Studio`, `BackRock-NeonCity`, `StarterAssets`, `Polytope Studio`, `yixuan-zzz`, `TextMesh Pro`, `TutorialInfo`, `!GET_MORE_ASSETS_FOR_FREE`. Do not refactor these.

**First-party gameplay code is only:**
- `Assets/Scripts/` — 8 C# scripts, organized in subfolders:
  - root: `PlayerController.cs` (third-person, **active**), `PlayerMovement.cs` + `MouseLook.cs` (first-person, older)
  - `UI/` — `HUDController.cs` (health bar), `SkillCooldownButton.cs` (cooldown skills)
  - `GunLogic/` — `AimController.cs` (hitscan; see gotcha below)
  - `Editor/` — `HumanoidConverter.cs`, `TextureSizeReducer.cs` (Editor-only batch tools, not runtime code)
- `Assets/MyAssets/` — character (`CyberSoldier`) and animations

## Architecture of the gameplay scripts

Two **parallel, mutually exclusive control schemes** exist. Know which one a scene uses before editing:

1. **Third-person (actively developed — see recent commits):**
   - [PlayerController.cs](Assets/Scripts/PlayerController.cs) — requires `CharacterController` + `Animator`. Movement is **camera-relative**: input direction is offset by `mainCamera.eulerAngles.y`, the character `Slerp`s toward the target angle, and `controller.Move` drives it. Applies its own gravity. The camera transform is auto-found via `Camera.main` if not assigned.
   - **Fly toggle:** `LeftShift` flips an `isFlying` flag that swaps `walkSpeed`→`flySpeed` and plays/stops the left/right thruster `ParticleSystem`s. The Animator `Speed` float is `0` (idle) / `0.5` (walking) / `1.0` (flying) — note `1.0` means *fly*, not run.
   - **Cinemachine 3.x integration:** uses `using Unity.Cinemachine;` and drives a `CinemachineCamera`. Scroll-wheel zoom adjusts `CameraDistance` on whichever of `CinemachineThirdPersonFollow` / `CinemachinePositionComposer` is present (clamped to `minZoom`/`maxZoom`). This is Cinemachine **3.x** API (`CinemachineCamera`, `PositionComposer`), not the 2.x `CinemachineVirtualCamera` / `FramingTransposer` — don't mix the two namespaces.

2. **First-person (older approach):**
   - [PlayerMovement.cs](Assets/Scripts/PlayerMovement.cs) — simple `transform.right/forward` movement via an assigned `CharacterController`, plus gravity.
   - [MouseLook.cs](Assets/Scripts/MouseLook.cs) — pitches the camera and yaws `playerBody`; `Escape` toggles cursor lock/look on and off.

Both schemes use the **legacy Input Manager API** (`Input.GetAxis`, `Input.GetKey`, `Input.GetMouseButtonDown`) rather than the new Input System, even though the Input System package and `Assets/InputSystem_Actions.inputactions` are present. Stay consistent with the legacy API when extending player input unless you are deliberately migrating.

### UI / combat system (ZZZ-style, the current direction)

- [SkillCooldownButton.cs](Assets/Scripts/UI/SkillCooldownButton.cs) — one per skill slot. Implements `IPointerClickHandler`, so a keyboard shortcut (`activationKey`) **and** a UI click both funnel through `TryUse()` → `Activate()`, which starts the cooldown. A radial-filled `cooldownOverlay` Image + optional countdown text visualize the cooldown. `Activate()` currently only `Debug.Log`s — hook real skill effects/damage/animation in there. This is the **no-ammo** model; don't reintroduce ammo counters here.
- [HUDController.cs](Assets/Scripts/UI/HUDController.cs) — action-style health bar: a filled `fillImage` colored by a `healthGradient`, with an optional `delayedFillImage` "damage trail" that eases toward the real value. `TakeDamage`/`Heal` are the public entry points. **Test keys** (`K` damage / `L` heal) are gated behind `enableTestKeys` — turn that off for real builds.

### Editor tools (under the Unity `Tools` menu)

Both live in `Assets/Scripts/Editor/` (so they compile only in-Editor) and are `EditorWindow`s opened from the menu bar — not gameplay:
- [HumanoidConverter.cs](Assets/Scripts/Editor/HumanoidConverter.cs) — **Tools ▸ "Chuyển Animation sang Humanoid"**. Batch-sets every `t:Model` in a folder (default `Assets/WizardAnimation`) to `animationType = Human` + auto-create avatar, then `SaveAndReimport()`.
- [TextureSizeReducer.cs](Assets/Scripts/Editor/TextureSizeReducer.cs) — **Tools ▸ "Giảm Size Texture Hàng Loạt"**. Scans all `t:Texture` under `Assets` and clamps any `maxTextureSize` above `targetMaxSize` (default 512) down, then reimports. Useful for trimming the heavy vendored texture packs.

### Gotcha: file/class name mismatch in gun logic

[AimController.cs](Assets/Scripts/GunLogic/AimController.cs) declares a class named `Gun` (not `AimController`). Unity **requires a MonoBehaviour's class name to match its filename** to attach it as a component, so this script cannot currently be added via the Inspector. If you touch this file, either rename the class to `AimController` or rename the file to `Gun.cs`. The class does hitscan shooting via `Physics.Raycast` from `fpsCam` on left-click and currently only `Debug.Log`s the hit — damage/range fields exist but are not yet applied.
